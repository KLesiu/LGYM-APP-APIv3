# LgymApi.IntegrationTests.csproj

- Purpose: end-to-end API tests.
- Contains: `WebApplicationFactory`, middleware/auth/serialization/localization coverage, and test persistence.
- API host characterization resolves the real `Program` options and exercises authentication/localization pipeline behavior without changing production composition.
- Rules: reuse integration helpers, prefer NSubstitute mocks for touched collaborators, and validate legacy contract compatibility for changed endpoints.
- Boundary: keep these tests at the API boundary, not unit-test scope.
- API startup coverage resolves the canonical AppConfig, enum lookup, and unit-conversion services alongside the command registry/dispatcher, the exact 25 Application and 3 Notifications API-adapter contracts, Identity password scheduler adapter, testing no-op push scheduler, and Notifications FCM provider from the real host composition.
- PostgreSQL lifecycle tests require `LGYM_TEST_POSTGRES`; their disposable factory migrates and seeds a unique leased database, then force-drops it during async disposal. Factory initialization rethrows the original failure after successful cleanup; if cleanup also fails, a redacted exception retains initialization as the primary cause and cleanup as correlated diagnostics. The sealed InMemory factory remains the default fast harness when the variable is absent.
- Run the complete IntegrationTests project, including PostgreSQL cases, with `pwsh -File scripts/run-postgresql-integration-tests.ps1`. The runner requires either Docker or an admin connection through `-ConnectionString`, scopes `LGYM_TEST_POSTGRES` to its process, applies no test-category filter by default, rejects TRX results with unexecuted cases, removes a runner-owned Docker container, and restores the prior process variable. `-TestFilter` is available only for an explicitly documented focused slice and never substitutes for the unfiltered PostgreSQL suite. The leased database factory drops each `lgym_it_*` database during disposal.
- PostgreSQL transaction tests prove Application-owned commit visibility and rollback cleanup from fresh contexts. They do not assign commit or transaction ownership to repositories.
- `PostgreSqlHangfireDurabilityTests` constructs the production non-Testing Hangfire PostgreSQL composition against one leased database, stops and reconstructs the provider around an enqueued `IActionMessageJob`, injects one captured-email failure through the existing `TestEmailSender`, and proves the eventual retry and replay guards without contacting SMTP or FCM.
- The PostgreSQL factory replaces only `AppDbContext`, `DbContextOptions`, `DbContextOptions<AppDbContext>`, and `IDbContextOptionsConfiguration<AppDbContext>`; unrelated EF Core registrations remain intact.
- Both integration factories inherit the production `Program` facade order and six-assembly mapping set before applying test overrides. They replace only the shared `AppDbContext` registration set, plus `IEmailSender` and `IPushProviderSender` with singleton captures installed after all module registrations.
- The InMemory factory uses `EnsureCreated`, never runs migrations in the `Testing` environment, and retains `EfUnitOfWork`'s no-op transaction path. The PostgreSQL factory explicitly applies the existing Infrastructure migrations before seeding and retains relational `EfUnitOfWork` transactions.
- `TestEmailSender` and `TestPushProviderSender` prevent test hosts from reaching SMTP or FCM while retaining observable captured attempts; focused tests that need provider outcomes may replace the push capture again through `WithWebHostBuilder` after the factory override.
- Coaching API coverage preserves focused-controller compatibility, legacy payload shapes, authorization, note and invitation behavior, and PostgreSQL replay of canonical and legacy durable envelopes without changing the single-context persistence topology.
- SignalR coverage uses long-polling `HubConnection` clients against the Testing host to prove two-user recipient isolation and post-event suppression after logout, self-deletion, account blocking, and injected account/session mismatch while an unaffected valid session still receives delivery.
- The endpoint matrix covers the 186-route inventory with one executable authorization-evidence profile per row. It rejects unresolved evidence and requires each locator to match the route, method, access class, facets, and required evidence categories.
- `Microsoft.AspNetCore.SignalR.Client` is centrally pinned and referenced by this test project for the real SignalR clients. It adds no project-reference edge or topology change.
- Integration output links Notifications-owned email templates to the stable `EmailTemplates/<Template>/<en|pl>.email` runtime layout used by the host factories.
- `PostgreSqlTutorialRowSecurityTests` uses a disposable leased database and generated maintenance/runtime roles to exercise the tracked staging activation script, parent/child isolation, pool cleanup, denied runtime escalation, and tutorial API parity. `PostgreSqlRuntimeGuardHardeningTests` proves startup rejects incomplete Hangfire privileges and policy semantic drift, while activation rejects altered predicates and a spoofed target environment against the independently stored database marker. The operator checklist is [`tutorial-rls-pilot.md`](../docs/security/tutorial-rls-pilot.md).
