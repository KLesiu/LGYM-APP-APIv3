# LgymApi.Notifications.csproj

- Purpose: stable code boundary for provider-neutral notification capabilities.
- Contains: provider-neutral Notifications contracts, read models, errors, event bridge, installation lifecycle, in-app fanout, push enqueue/delivery/retry/cleanup, Coaching intent policy, and the email provider/template stack. Established `LgymApi.Application.Notifications.*` and Task 7 compatibility namespaces remain source-compatible, but their policy implementation compiles from this assembly.
- Rules: keep direct references limited to BackgroundWorker.Common, Domain, Identity, Platform, and Resources. Its internal persistence seam and private provider configuration are friend-visible only to Infrastructure, UnitTests, and IntegrationTests.
- Boundary: do not add a DbContext, migrations, publicly exposed provider credentials, or a reverse Identity dependency. `INotificationsPersistenceContext` exposes only its five owned sets and typed entries for in-app and push messages.
- Session lifecycle integration: Notifications registers the scoped `PushInstallationSessionDisassociationAdapter` for Identity's `IAccountSessionDisassociationPort`. The adapter, lifecycle service, and repository contract forward only the account-session marker ID; the private persistence implementation performs the persisted-ID rebind, stages disassociation without committing, and leaves the Identity termination UoW boundary authoritative.
- EF coordination: `NotificationsModelConfigurationRegistrar` owns the five fixed-order mappings. Infrastructure retains the global phase coordinator, the single `AppDbContext`, migrations, and the scoped `INotificationsPersistenceContext` alias without assembly scanning.
- Composition: `NotificationsModule.AddNotificationsModule` is the policy and repository-registration facade; its configuration overload is the sole public email/provider registration path and validates/adds the private email stack plus FCM client, settings, retry mapping, and provider sender. `AddNotificationsApiAdapters` separately registers the three API compatibility adapters after Infrastructure composition. Repositories use only `INotificationsPersistenceContext`, stage changes, and preserve the configured email send lease through Infrastructure's narrow `AddNotificationsInfrastructure()` settings bridge. API binds the SignalR publisher as the host adapter, and Worker remains last for scheduler and runtime selection.
- Email templates: the twelve source files are under `EmailTemplates/<Template>/<en|pl>.email`; API and Integration projects link them to the unchanged `AppContext.BaseDirectory/EmailTemplates/<Template>/<en|pl>.email` runtime layout.
- Compatibility: preserve `DeliveryKey`, `(installation,type,eventId)`, cursor ordering, bounded retry/cancellation recovery, stale tombstoning, and Coaching's single eligible channel. Public contracts remain free of Worker/Common runtime types, provider credentials, and provider-private token handling; FCM credentials and tokens remain internal to Notifications.
